怎么读结论。这是粗估，用来排除明显不够的方案、确定量级；定方案前用 capplan 的 tune 和 bench 按实测曲线细算。最少卡数取显存、带宽、算力三项里最大的一项（标蓝的就是瓶颈），并按张量并行向上取 1、2、4、8 张。
换算口径。显存 =（量化文件大小 + KV 推荐池 + 每流固定状态）÷ 0.9。KV 只算全注意力层，线性注意力层每条流是固定大小的状态。带宽 = 单流速度 × 每步读取字节 ÷ 0.6，每步读取 = 被读到的权重 + 在跑请求的 KV（最低池，稀疏注意力按每流最多看的 token 数封顶）+ 线性状态；MoE 在并发时各条流选的专家不同，按 1 −（1 − 选中专家比例）槽位 估算被读到的专家比例。算力 = 冷 prefill 吞吐 ×（2 × 激活参数 + 注意力开销）÷ 0.4。多卡时每加一张按 85% 效率计。
画像依据。OpenRouter《State of AI》平均 prompt 6K+、输出约 400；编码 Agent 取 TraceLab（中位 119K 缓存前缀 / 875 新增 / 214 输出）与 GitHub Copilot 轨迹（中位 68K / 247）。每人每小时次数、在线率、RAG 与长文档画像为经验假设，有网关日志时优先校准。每次占槽时长 = 首 token 目标 + 输出 ÷ 单流速度。
